## 02:10 show-fixes [详情] 过滤条件前置（skills + mcp）

- 背景：`--show-fixes` 输出在 [详情] 区块里先看到统计再看到过滤条件，阅读路径不直观。
- 决策：在 `formatSkillsListText` 与 `formatResourceListText` 中新增 `appendFiltersIfNeeded()`；当 `showFixes=true` 时，先输出 `provider_filter/state_filter`，再输出 `providers_scanned/providers_matched/...`。
- 实现：通过局部 `filtersAppended` 防止过滤条件重复追加，保持非 `show-fixes` 场景行为不变。
- 验证：`swift test --package-path libs/Providers --filter NolonCoreCLIKitTests` 通过（162 tests）。
- 测试补强：新增顺序断言，确保 `provider_filter: codex` 出现在 `providers_scanned: 1` 之前。
- 风险：仅文本渲染顺序调整，JSON 契约未变；低风险。

## 02:14 show-fixes 健康场景去重（mcp/workflow）

- 目标（BDD）：当 `list --verbose --show-fixes` 且无异常时，输出应保持两层：机器摘要 + 一行自然语言健康摘要，避免“结论：全部健康...”与其它字段重复。
- 红灯测试：新增 `runner mcp verbose show-fixes uses unified healthy summary line`，先失败（缺少 `健康：...`，且存在 `结论：全部健康...`）。
- 实现：在 `formatResourceListText` 中移除 verbose 专用 `结论：全部健康...`，统一无异常场景输出 `健康：installed/total...` 一行。
- 绿灯验证：
  - `swift test --package-path libs/Providers --filter runnerMcpVerboseShowFixesUsesUnifiedHealthySummaryLine` 通过。
  - `swift test --package-path libs/Providers --filter NolonCoreCLIKitTests` 通过（163 tests）。
- 风险：仅文本输出去重与文案统一，不涉及状态计算与 JSON 协议；低风险。
