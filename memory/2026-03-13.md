## Gemini Token Trend 与账号区同步加载
- 用户继续反馈 `Gemini CLI / 用量 / 历史 Token 消耗` 没有显示骨架屏，而且没有和账号区同步 loading。
- 根因：
  - `ProviderUsageView` 之前只把 `isLoadingTokenTrend` 传给 `ProviderTokenTrendSection`
  - 但 `ProviderUsageViewModel.load()` 是先加载 outcomes / Gemini 账号，再在后半段启动 `refreshTokenTrend()`
  - 导致 Gemini 首屏 loading 时，账号卡已经在 skeleton，token trend 仍按“无 snapshot + 非 loading”走空态
- 实现策略：
  - `ProviderUsageViewModel` 新增 `shouldShowTokenTrendLoadingSkeleton`，把 Gemini/Codex 的主 loading 与 token trend loading 合并判定
  - `ProviderUsageView` 改为使用统一 loading 判定，保证首屏与刷新期间 token trend 骨架和账号区同步
  - `ProviderUsageViewModel.load()` 提前启动 token trend 刷新任务，减少它落后账号区半拍的情况

## Codex 账号池调度方案定稿
- 与用户确认：Codex 账号池后续实现采用双模式并行方案：
  1. `gateway`：本地统一 HTTP gateway，中转全部 Codex 流量并做 sticky / 负载均衡 / failover / 熔断 / 评分 / 诊断
  2. `directAutoSwitch`：不启用网关，但在 usage 自动刷新后，当当前活跃账号额度窗口剩余比例低于阈值时，自动切到下一个有余量账号
- 明确边界：
  - 不实现 RPC server / JSON-RPC 网络服务
  - 两种模式互斥，gateway 开启时禁用自动切号
  - 账号来源仅使用 `~/.nolon/codex/auth/*.json`
- 文档已落位：
  - `docs-dev/features/codex-account-pool-gateway-and-autoswitch-2026-03-13.md`
  - `docs-dev/dev/codex-account-pool-gateway-and-autoswitch-design-2026-03-13.md`
