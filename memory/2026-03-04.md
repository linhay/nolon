## CLI 插件运行态判定修复（2026-03-04）
- 问题：`nolon plugin start` 可能误报 running，但 `status` 紧接着显示 stopped。
- 根因：运行态探测用 `pgrep -f xcodemcpkit` 时，可能误命中包含参数文本的短命进程/父进程。
- 修复：
  - `runningServerPID` 的 pgrep 分支新增二次校验：按 pid 反查 command line，并用 `matchesRuntimeCommand` 过滤。
  - `startPlugin` 增加稳态校验：启动后需在 800ms 内发现运行进程，且 250ms 内不应立即退出，否则返回 `plugin_runtime_start_failed`。
- 新增测试：`runner plugin start returns error when runtime exits immediately`。
- 回归：`swift test --package-path libs/Providers --filter NolonCoreCLIKitTests`（199 tests）通过。
- 冒烟结果：临时 `NOLON_HOME` 下，`plugin start` 对秒退进程现在返回明确失败，不再误报 running。
- 插件运行秒退（SIGKILL 9）定位：`~/.nolon/bin/xcodemcpkit` 未签名会被系统直接 kill（`--help` 也返回 137，无 stderr）。
- 修复：`XcodeMCPKitInstallService` 在安装/升级后对 `xcodemcpkit` 与 `xcode-mcp-server` 自动执行 ad-hoc 签名（`codesign --force --sign -`）。
- 新增测试：`testInstallLatest_WhenInstallSucceeded_CallsBinarySignerForInstalledExecutables`，确保安装成功后两个可执行文件都经过签名步骤。
- 兼容处理：`XcodeMCPKitRuntimeService` 已将 exit code 9 + empty stderr 视为 stopped（不再误报 failed），并写入 pre-kill 输出快照。
- 插件管理页补齐卸载流程：已安装时显示 Uninstall 按钮，执行时先停止 runtime（force），再卸载二进制与插件目录；仅在 `mcps/xcodemcpkit.json` 含 `nolon_plugin.managed=true && plugin_id=xcodemcpkit` 时才删除全局 MCP 配置。
- 版本展示文案调整：`Installed` 在已安装但无版本元数据时显示 `Unknown`（不再显示 `-`）；`Latest` 在远端不可用时显示 `Unavailable`。
- 覆盖测试：PluginManagementViewModelTests 新增卸载用例 2 条；XcodeMCPKitInstallServiceTests 新增卸载用例 2 条并全部通过。
- 插件版本展示增强：当 `installed_version.txt` 缺失且插件二进制存在时，`PluginManagementViewModel` 会调用 `xcodemcpkit --version` 回填安装版本；解析首个语义化版本并标准化为 `v` 前缀。
- 回填优先级：持久化版本（installed_version.txt）优先于二进制探测结果。
