## Codex Gateway 基础调度内核
- 新增 `CodexGatewayCandidate` 和 `CodexGatewayScheduler`，把 gateway 首版选路规则独立成纯内核。
- 当前调度顺序固定为：
  - 过滤 `isSchedulable == false`
  - 过滤已打满并发的候选
  - 按 `priority` 升序
  - 同优先级按 `inFlightCount` 升序
  - 再按 `lastSelectedAt` 做 LRU
  - 最后按 `accountID` 做稳定 tie-break
- 新增 `CodexGatewayResponsesRoutingService`，把 `candidate provider + scheduler + forwarder` 组合成可注入的 `responsesHandler`。
- 现在 gateway 已经不只是“单上游固定转发”，而是有了“从候选上游里选一个再转发”的主干能力。

## Codex Gateway Sticky 与 Failover
- `CodexGatewayResponsesRoutingService` 已加入最小 sticky session 机制。
- sticky key 当前按：
  - `session_id`
  - `conversation_id`
  提取。
- 若 sticky 已绑定且该账号仍可调度，会优先命中该账号，不再先按 priority/load/LRU 排序。
- 已加入最小 failover：
  - `429`
  - `5xx`
  - transport throw
  都会触发切下一个候选。
- failover 成功后会把 sticky 重新绑定到新账号。
- 当前还没有 sticky TTL、持久化、错误统计和 metrics。
