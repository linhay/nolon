# Codex 网关卡片 UI 分组重构（2026-03-18）

## 背景
原有「计划选中」与「进入多选后选中」样式一致，且缺少网关卡片分组能力，导致账号归组操作不清晰。

## 目标
1. 网关卡片样式与普通账号卡片明显区分。
2. 普通账号支持拖拽加入网关卡片。
3. 支持从网关卡片移除账号。
4. 多选支持加入网关卡片（目标卡片选择器）。
5. 支持多张网关卡片并按 provider 独立存储。

## 范围与边界
- 本次仅实现 UI 分组层。
- 网关卡片不是独立 daemon 实例。
- 不改 `CodexGatewayKit` 的运行时控制与 CLI/API 行为。

## BDD 验收
1. Given 空存储，When 读取网关卡片，Then 返回空 cards。
2. Given provider A/B，When 分别写入网关卡片，Then 互不污染。
3. Given 卡片成员含重复/失效账号 ID，When 读写，Then 自动去重并清理失效项。
4. Given 普通账号卡片，When 拖拽到网关卡片，Then 账号加入并展示成员计数变化。
5. Given 多选账号，When 选择目标网关卡片，Then 全部选中账号批量加入。
6. Given 网关卡片成员，When 点击移除，Then 仅该卡片关系移除，不影响账号本体。
7. Given 多张网关卡片，When 删除其中一张，Then 仅该卡片被删除。

## 实现摘要
- 新增 `ProviderUsage` 持久化：
  - `CodexGatewayCard`
  - `CodexGatewayCardsState`
  - `CodexGatewayCardsStore`
- `ProviderUsageViewModel` 新增网关卡片状态与操作：
  - 新建/重命名/删除卡片
  - 单账号/多账号加入
  - 成员移除
  - 账号刷新后无效成员清理
- `ProviderUsageView` 新增网关卡片区域：
  - 与普通账号卡片分离的容器视觉
  - 卡片菜单（重命名/删除）
  - 空态提示
  - drop 高亮
  - 成员移除按钮
  - 多选加入目标卡片选择器（sheet）

## 回归关注点
1. Codex 原有导出 ZIP / sub2api 与多选流程不回归。
2. `codex` 与 `codex-xcode` 卡片状态隔离。
3. 账号列表变化时，卡片成员与账号集合保持一致。

## 增补（2026-03-18：账号列表菜单与按钮交互优化）
- 目标：按 Apple HIG 收敛操作密度，降低头部并排按钮数量，保留清晰主动作。
- 调整：
  1. Codex 头部在多选模式下改为「已选计数 + 批量操作菜单 + 完成（主按钮）」。
  2. 批量导出/加入网关/清空选择统一收敛到「批量操作」菜单，减少横向拥挤与误触。
  3. 普通模式仅展示一个主动作按钮（按当前场景自动选取），其余动作保留在 `…` 菜单。
  4. 按钮统一使用 `Label + SF Symbols`，强化可扫读性与一致性。

## 增补（2026-03-18：拖拽进网关失效修复）
- 问题：账号卡片拖拽到网关卡片时存在 payload 兼容性问题，导致 drop 不生效。
- 决策：
  1. 拖拽源改用强类型 payload（`CodexGatewayAccountDropItem`），避免纯文本拖拽解析不稳定。
  2. drop 目标保留 legacy `String` 兼容路径，防止历史拖拽数据或系统文本拖拽完全失效。
  3. 新增解析器 `CodexGatewayDropParser`，统一处理 legacy 文本中的 UUID 提取。
- 验收：
  1. Given 新拖拽 payload，When 拖入网关卡片，Then 能稳定加入成员。
  2. Given legacy 文本 payload，When 含 UUID，Then 仍能提取并加入成员。
  3. Given 非法文本 payload，When 拖入，Then 不产生误加入。

## 增补（2026-03-18：交互切换为点击选择账号）
- 背景：部分环境下拖拽交互仍不稳定，影响可用性。
- 决策：将主路径切换为“网关卡片点击添加账号 -> 弹窗多选账号 -> 确认加入”。
- 规则：
  1. 候选列表排除已在目标网关卡片中的账号。
  2. 账号顺序沿用当前账号列表顺序。
  3. 继续保留拖拽作为兼容通道，不作为主引导文案。
- 验收：
  1. Given 网关卡片，When 点击“添加账号”，Then 弹出账号选择列表。
  2. Given 已有成员，When 打开候选列表，Then 已有成员不再出现。
  3. Given 选择多个账号并确认，When 返回网关卡片，Then 成员数与列表同步更新。

## 增补（2026-03-19：拖拽移除后的交互收敛）
- 背景：网关交互已移除拖拽主路径，避免用户在不同环境下遇到拖拽不稳定。
- 决策：
  1. 网关加人主入口统一为“添加账号”弹窗与多选确认。
  2. 多选加入网关时，`pendingGatewaySelectionAccountIDs` 按当前账号列表顺序稳定输出，不再受 `Set` 无序影响。
- 验收：
  1. Given 多选集合顺序无序，When 打开“加入网关”选择器，Then 待加入账号顺序与账号列表顺序一致。
  2. Given 账号列表顺序变更，When 再次发起多选加入，Then 待加入顺序与新列表顺序一致。

## 增补（2026-03-19：选择账号弹窗分组信息）
- 背景：用户反馈“选择账号”视图信息密度不足，仅平铺列表不利于快速定位账号类型。
- 决策：
  1. 为网关“选择账号”弹窗增加分组 section（沿用 Codex 账号分组口径：Plus / OpenAI / Relay 等）。
  2. 组内账号顺序保持 `codexAccounts` 当前显示顺序，避免分组后顺序抖动。
  3. 每个分组 header 显示组名与数量，提升可扫读性。
- 验收：
  1. Given 候选账号包含多种类型，When 打开选择账号弹窗，Then 按分组展示并可见每组数量。
  2. Given 同组多个账号，When 渲染分组，Then 组内顺序与账号列表顺序一致。
  3. Given 目标网关已有成员，When 打开弹窗，Then 已在卡片中的账号不出现在任何分组。

## 增补（2026-03-19：分组头视觉强化）
- 决策：
  1. 分组头采用 `Label + Capsule` 视觉，展示图标、组名与数量。
  2. 按分组语义赋予颜色：OpenAI（主色）、Relay（信息色）、Plus/Pro（成功色）、其他（中性色）。
- 验收：
  1. Given 分组头渲染，When 查看弹窗，Then 每组具备明显视觉锚点与数量提示。
  2. Given 不同组类型，When 渲染，Then 色彩语义可区分且不影响可读性。

## 增补（2026-03-19：网关卡片去“卡中卡”并对齐账号网格）
- 背景：用户反馈网关区域呈现为“长条容器内嵌卡片”，视觉上仍是卡中卡，不像账号卡片。
- 决策：
  1. 网关卡片承载层从 `VStack` 切换为与账号区一致的 `LazyVGrid(columns: codexAccountColumns, spacing: 12)`。
  2. 保留网关 section 标题行（名称 + 数量），但不再承担外层容器壳视觉。
  3. 网关单卡继续使用 `AccountSummaryCard`，成员区域维持高度约束策略。
- 验收：
  1. Given 存在多张网关卡，When 渲染，Then 卡片按账号区同列网格排列，不出现整条拉满容器。
  2. Given 窗口宽度变化，When 重排，Then 网关卡列数与账号卡同步变化。
  3. Given 网关候选分组弹窗，When 打开，Then 分组头（图标/组名/数量）保持可见并可选择账号。

## 增补（2026-03-19：添加按钮独立一行 + 右上菜单迁移右键）
- 背景：用户反馈网关单卡头部仍显拥挤，且右上角 `...` 与主操作并存造成视觉负担。
- 决策：
  1. 将“添加账号”改为网关卡内独立一行主按钮，不再与标题行并排。
  2. 移除卡片右上角 `...` 菜单入口。
  3. 保留重命名/删除操作，但迁移到卡片 `contextMenu`（右键菜单）中。
- 验收：
  1. Given 网关卡渲染，When 查看卡片头部，Then 不再出现右上角 `...` 菜单。
  2. Given 用户需要添加成员，When 查看卡片，Then “添加账号”以独立一行显示且可点击。
  3. Given 用户右键网关卡，When 打开右键菜单，Then 可见“重命名/删除”操作。

## 增补（2026-03-19：选中网关即激活，空网关自动弹添加账号）
- 背景：用户希望网关卡点击行为与“当前激活目标”一致，且空网关卡不再需要二次点击“添加账号”。
- 决策：
  1. 点击网关卡时，立即将该卡写入 `lastUsedCardID`，作为当前激活网关目标。
  2. 若被点击网关卡成员为空，自动弹出“添加账号”弹窗，减少空卡配置路径步骤。
  3. 若网关卡已有成员，仅执行激活，不自动打断当前视图流。
- 验收：
  1. Given 网关卡有成员，When 点击网关卡，Then 卡片被激活且不自动弹“添加账号”。
  2. Given 网关卡无成员，When 点击网关卡，Then 卡片被激活并自动弹“添加账号”。

## 增补（2026-03-19：网关区域与弹窗补齐 Page Marker）
- 背景：用户要求对未提交的网关相关视图补齐 page marker，便于调试定位与回归追踪。
- 决策：
  1. 网关 section 增加 `debugCardLocator`，标记路径包含“网关卡片”。
  2. 网关单卡追加卡名 marker，便于按卡片级别定位。
  3. “为 XXX 选择账号”弹窗补齐 marker，保证弹层流程可定位。
- 验收：
  1. Given 打开 Usage 页面，When 定位网关区，Then 可命中“网关卡片” marker。
  2. Given 存在多张网关卡，When 定位单卡，Then marker 包含对应卡名。
  3. Given 打开添加账号弹窗，When 检查定位路径，Then 包含“为 XXX 选择账号”。

## 增补（2026-03-19：网关与账号选中态互斥）
- 背景：用户明确要求“网关卡与账号卡不应同时为选中态”。
- 决策：
  1. 网关卡选中时，账号卡不再显示 active 选中视觉。
  2. 点击账号卡时，先清空网关卡选中状态，再执行账号卡原有交互。
  3. 账号激活成功后，强制清空网关卡选中状态，保持单一选中源。
- 验收：
  1. Given 网关卡已选中，When 查看账号网格，Then 不出现账号 active 高亮。
  2. Given 网关卡已选中，When 点击任意账号卡，Then 网关卡选中态被清空。
  3. Given 网关卡已选中，When 确认激活账号，Then 网关卡选中态清空且不共存。
