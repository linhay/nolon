# 2026-03-31

## 关键变更：全 Provider Skills 软链开关

- 新增 `Provider.skillsLinkEnabled`，默认 `false`，兼容旧配置缺省值。
- 新增 `ProviderSkillsLinkService`，实现按 provider 的 skills 软链开启/关闭流程：
  - 开启前 preflight 校验；
  - `skills` 目录为空时直接切换；
  - 非空时支持「备份并切换」与「直接切换」；
  - 备份固定目录为 `skills.bak`，存在则先覆盖删除；
  - 关闭时优先恢复 `skills.bak`，无备份则回落空目录。
- Provider 详情页已接入开关与确认弹窗；仅作用 `skills`，不影响 workflows/rules/prompts。
- 交互调整：`skills` 页面不再展示内联设置卡片，改为“搜索框右侧菜单按钮”承载开关与路径信息；相关视图下沉到 `NolonUI`。
- 扫描状态对“provider skills 根目录软链到全局 skills 根”的场景统一按 `installed` 判定，避免误报 orphaned。

## 关键变更：Codex 导入阶段凭证换取与账号信息补全

- 在 `CodexAuthManager.validateImportAuthFiles` 增加导入候选补全流程：
  - 先做现有 JSON 归一化；
  - 若仅有 `refresh_token` + 残缺 OAuth token，自动执行 refresh token 换取，补齐 `id_token/access_token`；
  - 从 JWT claims 提取并回填 `email`、`chatgpt_account_id/account_id`、`plan_type/plan`；
  - 在可形成 OAuth token 对时自动补齐 `auth_mode=chatgptAuthTokens`。
- 新增可注入的 `refreshCodexTokenAction`，默认走 OpenAI `oauth/token` 刷新端点；测试可注入 mock，避免真实网络依赖。
- 导入面板候选数据改为展示“补全后的结果”，并保持只读（不允许编辑凭证）。

## 关键变更：导入面板支持自定义分组并直写 SQLite

- `ProviderUsageEngine` 新增导入目标状态：
  - `managedSnapshots`（默认，原有账号快照导入流程）
  - `customSQLiteGroup`（自定义分组，导入时直写 SQLite）
- 导入面板（`CodexImportSheet`）新增“导入目标”分段选择与自定义分组名称输入框：
  - 选择自定义 SQLite 分组时，分组名必填；
  - 候选账号信息仍保持只读，不支持编辑。
- `CodexAuthManager` 新增 `ImportDestination`，`importValidatedAuthFiles` 支持按目标导入：
  - 默认仍创建账号快照文件；
  - 自定义分组模式写入 `~/.nolon/codex/imports.sqlite3`。
- SQLite 持久化设计：
  - 表 `custom_import_groups`：记录分组定义；
  - 表 `imported_codex_accounts`：记录导入账号原始 auth JSON 与元信息；
  - 使用 `(group_id, auth_hash)` 唯一约束实现同组去重 upsert，避免重复导入膨胀。

## 关键变更：Codex 账号体系主路径迁移到 SQLite

- `CodexAuthManager` 新增账号库 SQLite 主存储：`~/.nolon/codex/accounts.sqlite3`，核心表：
  - `codex_accounts`（账号索引：id/name/created_at/relative_auth_path）
  - `codex_active_accounts`（provider -> active account 映射）
- 迁移策略：
  - 首次访问时自动创建 schema；
  - 若 SQLite 为空，自动把现有 `auth/*.json` 快照账号导入 SQLite；
  - 兼容导入旧 `active-accounts.json` 到 `codex_active_accounts`。
- 读写策略：
  - `loadAccounts`、`addAccount`、`updateAccount`、`add/update configured account`、`deleteAccount` 都会同步/使用 SQLite 索引；
  - 仍保留 auth 快照文件用于现有运行时激活（symlink 机制不变），避免一次性破坏兼容路径。
- 一致性策略：
  - 每次加载会校验 SQLite 中记录对应的 auth 文件是否存在/可导入；
  - 无效记录自动清理；
  - 对 auth 目录中“SQLite 未登记”的遗留文件自动回填入库。
