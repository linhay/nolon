## Usage 顶部轨道对齐修正
- 用户继续反馈 `Codex -> Usage` 顶部 rail 的对齐方式仍然不对，核心问题不再是“控件有没有缩小”，而是布局算法还保留了 `left controls + spacer + right actions` 的分裂结构。
- 这轮在 `NolonUI` 做了三件事：
  - `workspaceControlDeck` 改为 leading-aligned 的单轨道布局，优先单行，空间不足时用 `ViewThatFits` 回退为两行左对齐；
  - `Bucket` 菜单控件移除内部 `Spacer`，改成 `title + chevron.down` 的紧凑 inline pill；
  - `ProviderTokenTrendToolbarField` 只有在显式给宽度时才锁宽，否则按内容自然收缩，避免继续制造虚胖空白。
- 新增回归：
  - `NolonUITests.testProviderTokenTrendMenuControl_GivenCompactTitle_UsesTightIntrinsicWidth`
  - `ProviderTokenTrendSectionViewTests.testProviderTokenTrendSectionView_GivenIntradayToolbarControls_WhenRenderingWideHeader_ThenKeepsCompactRailLayout`

## Usage 顶部轨道第二轮收口
- 第一轮修正后，用户继续反馈顶部 rail 仍不够像同一条轨道；进一步排查确认真正根因是 `primaryToolbarRow` 仍带 `maxWidth: .infinity`，单行时会吞掉剩余宽度，把 `Bucket / Refresh` 挤成右侧动作区。

- 同步给 `ProviderTokenTrendToggleControl` 补了 intrinsic width 约束，并收紧 `ProviderTokenTrendToolbarRail` 的内边距，让顶部交互更像紧凑的 instrument rail。
- 验证结果：

  - 顶部轨道相关新增控件宽度测试通过；
  - `git diff --check` 通过；
