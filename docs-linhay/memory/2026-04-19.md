## Codex Sessions SQLite 容错
- 根因：`CodexSessionStore.loadStateIndex(in:)` 会把单个 `state_*.sqlite` 的打开失败直接抛出，导致整个会话页加载失败，和既定“warning + skip”降级策略不一致。
- 修复：对每个 `state_*.sqlite` 单独捕获 SQLite 读取错误；失败时发 `CodexSessionStore.warningNotification`，附带 `database_path`，并跳过该坏库继续合并其余状态库。
- 新增回归：存在一个不可读 `state_bad.sqlite` 且同时存在正常 `state_4.sqlite` 时，`loadSnapshot` 仍成功，且会记录 warning。
- 验证：`swift test --package-path libs/Providers --filter CodexSessionStoreTests` 通过，日志中已确认 warning 文案包含 `skipped unreadable state database ... unable to open database file`。

## Codex Sessions 缓存入口语义补强
- 时间：2026-04-20 00:37:27 +0800
- 根因确认：工程里确实同时存在文件级 projection cache 和 SQLite usage index，但此前 `CodexSessionsTabViewModel` 只在 `reload(mode: .initial) && allRows.isEmpty` 时读取 projection cache，因此“复用中的单例 view model 再次进入会话页”通常不会先展示缓存。
- 结论：会话页的持久化缓存需要从“仅首次空白加载的兜底”提升为“进入页默认展示源”；SQLite usage index 继续只承担 usage/search/sort 预热，不负责列表结构展示。
- 实现：`handleViewAppearance()` 在 stale refresh 前先调用统一缓存展示入口；`refresh()` / `reload(mode: .refresh)` 也会先尝试应用 cached snapshot 或 cached skeleton，再后台走 fresh snapshot reconcile。
- 保留策略：只有 `initial + cached snapshot clean/fresh` 时才短路全量 reconcile；是否展示缓存，不再受 `mode == .initial` 和 `allRows.isEmpty` 限制。
- 回归用例新增两条：`GivenLoadedSessionsPageAndCachedSnapshot_WhenViewAppearsAfterStaleInterval_ThenCachedRowsAppearBeforeRefreshCompletes` 与 `GivenLoadedSessionsPageAndCachedSnapshot_WhenRefreshing_ThenCachedRowsAppearBeforeSnapshotReloadCompletes`，锁定“先缓存后对账”的用户可见语义。
