- 新增 `CodexConfigStore`，按 `config.toml` 路径串行化 read-modify-write，减少多模块并发/交错写入导致的配置丢失。
- 第二阶段补上跨进程 `.lock` 文件互斥和原子写，避免子进程或仓外同机写入绕过进程内锁。
- 已将 `CodexBinaryManager`、`MCPConfigManager`、`CodexActiveProviderConfigManager`、`NolonCodexCLI.prepareIsolatedLoginHome`、Codex 高级配置保存迁移到统一 store。
- 后续审计又补掉两个 app 侧旁路：`ProviderUsageEngine.prepareCLILoginHomeDirectory` 和 `CodexConfigEditorView` 全文编辑保存，现在 Codex 生产写路径都经过 `CodexConfigStore`。
- 继续排查发现切账号仍会丢项，根因在 `CodexActiveProviderConfigManager.restoreManagedConfig`：它会把 relay 激活时缓存的 `originalRawConfig` 整份回写，覆盖 relay 激活后 app 内新增的 MCP 等片段。已改为“从当前文件剥离 managed fragment，再补 baseline 受控键”。

- 继续推进后确认仅补官方字段还不够：`setEnabled` 一类局部写回仍会吃掉未知 server 键、未知工具字段和未知子表。已把 Codex MCP 写回改成基于现有 TOML block 的局部 merge，明确遵循“preserve unknowns”策略，并新增回归覆盖未知字段保留。
- 基于这轮排查与修复，单独创建 `docs-linhay/spaces/20260427-codex-config-governance/`，把 Codex 配置写入收口、MCP unknown-preserving、旁路审计与门禁需求升级为正式治理 space。
- 继续推进治理落地时又发现一个真实旁路：`ProviderMcpGridView` 在创建原生 MCP 配置文件时会直接写 `defaultMcpConfigPath`，对 Codex 即直写 `config.toml`。已改成共享入口 `MCPConfigManager.ensureNativeConfigScaffold(for:)`，并新增 `scripts/tests/codex-config-governance-smoke.sh` 扫描典型 Codex 配置直写旁路。
