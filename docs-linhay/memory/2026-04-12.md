## Codex 启动缓存预热与重登录局部刷新
- 现象：
  - 启动 APP 首次进入 Codex 用量页时，没有先展示 SQLite 里已有的上一轮 usage cache。
  - 初次刷新时，失败过的非当前账号会被跳过，看起来像“只刷新当前账号”。
  - 对单个账号执行“重新登录”后，会触发全量 `load()`，导致所有账号都被刷新；若其中若干账号刷新失败，旧额度会被 failure 结果覆盖，看起来像“所有额度都消失了”。
- 根因：
  - `loadIfNeeded()` 之前直接进入 `load()`，没有先把 SQLite 里的 Codex 账号与缓存 outcome 水合到内存。
  - `refreshCodexAccountsOnInitialLoad(...)` 之前复用了 `shouldSkipRefresh(...)` 过滤，任何带 `lastSyncFailedAt` / failure message 的非 ChatGPT 账号都会在启动初刷被跳过。

  - `shouldRetainExistingCodexSuccessResult(...)` 之前只在 `CodexHTTPUsageQueryError` 时保留旧 success；其他失败类型会直接把已有 quota success 覆盖成 failure。
- 修复：
  - `ProviderUsageEngine.loadIfNeeded()` 现在先执行 `hydrateCachedStateForInitialLoadIfNeeded()`，先把 SQLite/快照里的 Codex 账号与缓存卡片灌进内存，再进入正式 `load()`。
  - `refreshCodexAccountsOnInitialLoad(...)` 改为按显示顺序全量刷新，不再因为既往 failure summary 跳过账号。
  - `schedulePostLoginReload(...)` 在“重新登录已有账号”场景下改为 `reloadCodexFromDisk(refreshUsage: false)` + 定点 `refreshCodexAccountOutcome(...)`，不再调用全量 `load()`；新增账号登录仍走原有全量加载。
  - `shouldRetainExistingCodexSuccessResult(...)` 改为只要已有 success quota，就在刷新失败时保留旧 success 展示，同时把新的 failure message 写进 summary。

## Codex API Key 账号失败态与额度持久化修复
- 时间：2026-04-12 02:40:00 CST
- 现象：
  - `official API key` 账号在“全部账号刷新”失败后会显示“重新登录/同步失败”等错误语义。
  - 刷新或清理失败元数据后，之前的额度缓存会一起消失，导致重启或刷新后额度不显示。
- 根因：
  - SQLite 存储里同时存在两类 payload：
    - 运行时最小 `auth.json` materialized payload
    - 含 `usage_cache` / `lastSync*` / `custom_group_name` 的完整存储 payload
  - 之前内部读写复用了最小 payload 去执行 `storeUsageCache`、`clearSyncFailure`、`updateSyncFailure` 等写回，导致 SQLite upsert 时把未出现在最小 payload 里的 `usage_cache_json` 和同步失败元数据覆盖成空。
  - CLI 展示层也在用最小 payload 读 summary / sync failure，导致 `API key` 账号被误判成需要重新登录，旧额度也读不回来。
- 修复：
  - `CodexAuthManager+SQLite.swift` 给 SQLite 读回增加 `includeManagedMetadata` 开关，区分“最小运行时 payload”和“完整存储 payload”。
  - `readAccountAuthData(...)`、`accountAuthDataWithoutMaterialization(...)` 改为读取完整存储 payload，保留 `nolon.account`、`usage_cache`、`lastSync*` 等字段；`accountAuthData(...)` 继续保留最小 materialized 行为，不往运行时 `auth.json` 塞多余字段。
  - `NolonCodexCLI.swift` 读取账号 summary / sync failure / token info 时切到完整 payload，保证 `official API key` 账号不会再被映射成 `needsReauth/failed`。
  - 既有修复继续生效：`official API key` 刷新失败时只清空 failure metadata，不清缓存、不显示 relogin/copy error。
