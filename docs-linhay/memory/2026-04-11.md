## Codex 手动刷新强制抓额度

  - 自动轮询、首屏预加载和按计划刷新仍保持原来的 `settings.includeCredits`，避免后台负载被一并抬高。
  - 本机偏好同步修正：`nolon.usage.settings.template.codex` / `codexXcode` 以及当前 provider 级 key 已改为 `includeCredits = true`、`codexHideZeroQuotaAccounts = false`。

## MCP linked sync provider 归属修正
- 现象：MCP linked 模式把 `~/.nolon/mcps` 的所有 fragment 全量投影回 provider config，未按 `x-nolon.providers` 过滤；同时删除 provider MCP 时，最后一个 provider 解绑后会把 fragment 留成“全局可见”，导致同名 MCP 从 cache 重新冒出来。
- 实现：
  - `MCPConfigManager.syncAllCacheServersToProvider(for:)` 增加 `entry.applies(to:)` 过滤，只同步当前 provider 绑定的 fragment。
  - `unbindProviderFromCacheServer(name:provider:)` 在最后一个 provider 解绑后直接删除 fragment 文件，不再把它降成无 owner 的全局 fragment。
  - 新增回归测试 `linkedMcpSyncRespectsFragmentProviderOwnership`，覆盖“Codex 同步时不得污染 OpenCode fragment provider 元数据”的场景。
- 风险结论：
  - Codex `.toml` 写回仍然是 `CodexMCPConfig + TOMLEncoder` 整文件重写，未知字段、注释和额外 section 仍有被裁剪风险；如果后续继续收到“config.toml 被异常改写”的反馈，需要把 MCP 写入链路改成文本级 patch，而不是 typed round-trip。
- 验证：
  - `swift test --package-path libs/Providers --filter NolonResourceKitTests` 中新增 linked-provider-scope 用例通过，`removeServer` 回归也已恢复。
  - 同轮仍有现有失败未收敛：`ProviderMCPMaintenanceService provides snapshot and single-cache update` 的 cache 状态预期与当前“upsert 即写 cache”语义不一致；`Provider resource snapshot does not rewrite native MCP config when provider MCP link is disabled` 在断言前就观察到 `config.toml` 已存在，需继续单独排查路径/环境来源。

## MCP config 根因修复：启动投影 + HOME 路径 + Codex 非法字段
- 现象：
  - 用户反馈每次启动 app 后，Codex `config.toml` 又出现 `http_headers is not supported for stdio`。
  - 现场确认毒源是 `~/.nolon/mcps/playwright.json` 中残留测试夹具值（`cache-cmd` / `from-cache` / `x-token=abc`），启动期 linked MCP sync 会把 fragment 重新投影到 provider 原生配置。
- 根因：
  - `ProviderTemplate` 默认路径解析硬绑 `NSHomeDirectory()`，测试切换 `HOME` 时不能稳定隔离到临时目录，存在把夹具写进真实用户目录的风险。
  - Codex/CodexXcode 的 MCP 投影链路对 cache fragment 没做 provider-native 约束校验，`stdio` fragment 里的 `http_headers` 会被原样写入 `config.toml`。
- 实现：
  - `ProviderTemplate` 改为优先读取 `ProcessInfo.processInfo.environment["HOME"]`，只有缺失时才回退 `NSHomeDirectory()`。
  - `MCPConfigManager` 新增 provider-specific sanitize：
    - 对 `codex` / `codexXcode`，若目标 server 是 `stdio`（显式 `type=stdio/local` 或隐式有 `command`），投影前移除 `url`、`http_headers`、`env_http_headers`、`oauth_resource`、`scopes`。
  - 补充回归测试：
    - `ProviderTemplate default paths respect current HOME environment`
    - `Linked MCP sync strips unsupported Codex stdio HTTP header fields`
  - 同步更新旧测试语义，承认当前 `upsertServer/setEnabled` 会同步更新 cache。
- 验证：
  - `swift test --package-path libs/Providers --filter NolonResourceKitTests` 已通过，64 个用例全部通过。
