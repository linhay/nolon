  - 组头 usage 改为按整组全部 session 聚合，不再依赖折叠态可见 rows
  - 保持“组头聚合来源”和“列表当前可见 rows”两条数据链路分离

## Micro-Sync 09:08
- 修复 `SkillInstaller.scanProvider(...)` 在“provider 的 `skills` 根目录本身是 symlink，且直接指向全局 skills 根”场景下漏扫已安装技能的问题。
- 根因定位：
  - `SkillInstallRootResolver.resolvedScannableFolder(...)` 之前先判断 `isFolderExists`，会在 direct-linked root 场景直接返回原始 symlink 路径。
  - `SkillInstaller.scanDirectory(...)` 依赖这个返回值继续枚举，导致 `testBDD_GivenDirectLinkedProviderRoot_WhenScanningInstalledSkill_ThenMarkInstalled` 场景下扫描结果缺失 `karpathy-guidelines`。
  - 同类逻辑的 ancestor-linked root 场景本身不受影响，因为最终节点不是 symlink。
- 本轮实现：
  - 调整 `libs/Providers/Sources/NolonResourceKit/Infrastructure/ProviderSkillsLinkService.swift`
  - `resolvedScannableFolder(...)` 改为优先解析最终节点 symlink 的真实目录，再回退普通目录判断
  - 保持外部 reported path 不变，只修正扫描入口
- 验证结果：
  - `xcodebuild test -skipPackageUpdates -project nolon.xcodeproj -scheme nolon-app -destination 'platform=macOS' -only-testing:nolonTests/SkillInstallerTests/testBDD_GivenDirectLinkedProviderRoot_WhenScanningInstalledSkill_ThenMarkInstalled -only-testing:nolonTests/SkillInstallerTests/testBDD_GivenParentLinkedProviderRoot_WhenScanningInstalledSkill_ThenMarkInstalled` 通过
  - `xcodebuild test -skipPackageUpdates -project nolon.xcodeproj -scheme nolon-app -destination 'platform=macOS' -only-testing:nolonTests/SkillInstallerTests` 通过
