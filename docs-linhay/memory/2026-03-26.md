# 2026-03-26

## NolonUI 组件范式整改（全量推进）

- 决策：将 `libs/NolonUI` 从“仅挂载空 ViewModel”升级为“组件内部 UI 状态迁移到对应 `@Observable` ViewModel”的实质落地模式，确保组件与 ViewModel 关系不止命名层面。
- 变更范围：`ComponentViewModels.swift` 与 7 个组件文件，覆盖删除确认弹窗状态、卸载确认状态、hover 状态、分栏可见性状态。
- 关键动作：
  - 在 `ComponentViewModels.swift` 新增可观测状态字段：`columnVisibility`、`showingDeleteConfirmation`、`showingUninstallConfirmation`、`isHovered`。
  - 组件侧将本地 `@State` 迁移为 `viewModel` 状态绑定（例如 `isPresented: $viewModel.showingDeleteConfirmation`）。
- 验证结果：执行 `xcodebuild test -project nolon.xcodeproj -scheme nolon-tests -destination 'platform=macOS'`，结果通过（`532` tests，`0` failures，`1` skipped）。
- 风险记录：其余无本地行为状态的组件当前仍为“轻量 VM 持有”模式，后续若新增行为状态需继续遵循“优先入 ViewModel”。

## 主工程视图范式门禁强化（继续整改）

- 决策：将“主工程 View 与 ViewModel 一对一”从命名约定升级为显式绑定约束，新增 `ViewComponentBindable` 协议并要求每个主工程 `View` 提供 `ComponentViewModel` 类型绑定。
- 变更范围：新增 `nolon/Skills/Shared/UI/ViewComponentBindings.swift`；增强 `nolonTests/ViewComponentParadigmTests.swift`。
- 关键动作：
  - 为主工程视图补齐 `extension Xxx: ViewComponentBindable { typealias ComponentViewModel = XxxViewModel }`。
  - 测试新增绑定检查：除 `@Observable` ViewModel 存在性外，强制存在 `ViewComponentBindable` 扩展。
- 验证结果：
  - `xcodebuild test -project nolon.xcodeproj -scheme nolon-tests -destination 'platform=macOS' -only-testing:nolonTests/ViewComponentParadigmTests` 通过。
  - `xcodebuild test -project nolon.xcodeproj -scheme nolon-tests -destination 'platform=macOS'` 全量通过（日志 `/tmp/nolon-fulltest.log`，`TEST SUCCEEDED`）。
- 风险记录：当前绑定采用类型别名约束，尚未强制注入实例；后续若需要可进一步升级为“View 持有对应 ViewModel 实例/依赖注入”级别的静态检查。
