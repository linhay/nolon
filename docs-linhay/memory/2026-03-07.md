## Codex 导入流程改造

- 将 Codex 账号导入从 `fileImporter -> 校验 alert -> 直接导入` 改成独立 modal 流程。
- 导入 modal 支持拖拽或选择 `.json` / `.zip`，文件进入后先生成候选账号列表，再由用户勾选导入。
- 导入候选列表现已按“导入来源”分组展示：
  - 单个 JSON 单独成组
  - 同一个 ZIP 内的候选项归为同一组
  - 支持整组选中/取消整组，以及全局全选/取消全选
- 参考 Gemini CLI 的一轮 UI 审稿后，导入 modal 又做了轻量视觉收口：
  - Drop zone 内 `选择文件` 升为主按钮，`粘贴` 保持次按钮
  - 底部主按钮动态显示选中数量，如 `导入 3 个账号`
  - 校验/联通测试期间在底部展示全局进度
  - 全局错误改为 banner，而不是普通 caption 文本
- 合法候选项会自动复用现有 detached Codex 用量链路测试连接；测试失败项仍允许导入，但用户可手动取消勾选。
- modal 关闭即丢弃本次导入草稿状态，不导入 active registry，也不自动激活账号。
- Codex 导入与复制链路继续补齐：
  - 账号卡片菜单新增 `Copy Auth JSON`
  - 导入 modal 新增 `粘贴` 入口，支持直接粘贴 auth JSON
  - 导入 modal 也支持解析 localhost 登录回调 URL，包括 `/success` 和 `/auth/callback`
  - 兼容只有 `id_token` 的 success URL 恢复导入场景
  - 回调 URL 会先转换成兼容的 auth JSON，再复用现有校验、候选列表和自动连接测试链路
- Codex 登录链路收口为只走 app-server：
  - 不再 fallback 到 direct CLI OAuth
  - app-server 登录失败时直接显示错误
  - 避免 upstream direct CLI 默认自行拉起浏览器
- Codex 登录 URL 弹窗去掉重复关闭语义：
  - 顶部 `Close` 改为唯一的 `取消登录`
  - 不再同时保留两个等价的结束动作
