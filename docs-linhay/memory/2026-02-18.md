# 2026-02-18

## CLI 体验驱动修复（codex auth）

1. 修复 `nolon codex auth usage` 总览中 `[账号]` 与 `[用量]` 激活账号标记不一致的问题。
- 决策：总览渲染统一以 `[状态]` 中 `active_account_id` 为唯一真值，覆盖两个区块的 active 标记。
- 代码：`NolonCodexCLIExecutor.formatAuthOverview/formatAuthList/formatAuthUsageAccounts`。
- 测试：新增 `auth usage overview resolves active account consistently by status`。

2. 修复 `nolon codex auth refresh --email <x>` 成功后行状态仍显示“未激活”的问题。
- 根因：`authRefresh` 使用刷新前快照 `activeAccountID` 写入 `items.isActive`。
- 决策：刷新完成后重新读取最终 active account，并回填所有 `items.isActive`。
- 代码：`NolonLiveCodexCLIService.authRefresh`。
- 测试：`auth refresh performs silent token refresh and does not return login URL` 增加 `isActive == true` 断言。

3. UI 文案小优化
- `auth usage` 的来源字段从 `-` 改为 `旧缓存`，避免歧义。
- `auth activate` 交互列表改为固定列（编号/状态/邮箱/用量/账号ID）。

4. Ctrl+C 取消登录体验优化
- 场景：`nolon codex auth login` 在 Ctrl+C 时此前仅显示 `^C`，缺少结构化错误上下文。
- 改动：
  - `NolonCLIEntrypoint.execute` 对 `CancellationError` 映射为 `{"error":{"code":"interrupted","message":"Operation cancelled"},"ok":false}`，exitCode=130。
  - `NolonCLIApp` 先输出 stdout/stderr，再按信号态决定 `exit(130)`，避免中断信息被吞。
- 验证：TTY 实测 Ctrl+C 后输出 `interrupted` 错误 JSON，且无 `codex login` 残留进程。

5. 登录取消输出可读性修复
- 体验问题：`nolon codex auth login` Ctrl+C 时显示 `^C{...}` 粘连，错误 JSON 不易读。
- 修复：中断场景写 stderr 前补换行，输出为两行：`^C` 与结构化错误 JSON。
- 同时保持：退出码 130、错误码 `interrupted`、无登录残留进程。

6. 全量刷新不再篡改当前激活账号
- 体验问题：`nolon codex auth refresh`（不带 target）会将 active account 漂移到最后一个被刷账号。
- 修复策略：
  - 仅在全量刷新场景下记录刷新前 active account；
  - 全部刷新完成后执行恢复激活（优先走 authActivator，失败回退到 `activateAccountAndMarkActive`）。
- 验证：实机 BEFORE/AFTER `active_account_id` 一致。

7. refresh 结果表激活标记一致性
- 体验问题：全量 `auth refresh` 后，`status.active_account_id` 与 refresh 结果表 `isActive` 曾短暂不一致。
- 修复：全量刷新场景下，若成功恢复到原 active，则 refresh 返回项直接按“保留 active id”标记；避免依赖一次不稳定探测。
- 测试：`NolonCodexCLIServiceTests` 增加结果项 active 断言。
- 实机：refresh 前后 active 一致，表格星标与 status 一致。

8. 顶层 help 路由修复 + refresh 语义文案对齐
- 体验问题：`nolon help codex auth refresh` 返回 `Unsupported parsed command type: HelpCommand`。
- 修复：`NolonCLIEntrypoint.normalizeHelpArguments` 支持 leading `help` 语法，转发为 `<path> --help`。
- 额外对齐：`auth refresh` 帮助文案明确“targeted refresh 会切换 active 账号”。
- 测试：新增 `leading help command resolves codex action help`。

9. refresh --help 行为语义补全
- 体验结论：刷新行为已经正确（targeted 会切换 active；全量保留 active），但 `--help` 之前未完整表达。
- 修复：`NolonCodexAuthRefreshCommand` 增加 abstract，`--help` 输出 `OVERVIEW` 明确“无 target 保持 current active”。
- 测试：`codex auth refresh --help prints action help` 增加文案断言。

10. usage 旧缓存提示
- 体验问题：`auth usage` 出现 `来源=旧缓存` 时，用户不清楚是否需要手动刷新。
- 修复：在 usage 表格下追加提示：建议执行 `nolon codex auth usage --refresh` 更新来源与 Tokens。
- 测试：`routes auth usage per-account table` 增加提示断言。

11. refresh 帮助补充（ArgumentParser 原生 help）
- 体验问题：`nolon codex auth refresh --help` 未明确“无 target 保持 active”。
- 修复：给 `NolonCodexAuthRefreshCommand` 增加 abstract，生成 `OVERVIEW` 说明。
- 验证：`--help` 输出包含 keeps current active account。

12. Tokens 改为统一汇总输出（不按账号）
- 需求：当 token 无法稳定按账号归因时，不再做账号级 token 展示。
- 改动：`auth usage` 账号表移除 `Tokens(1d/30d/全量)` 列；改为在表格下统一输出 `Tokens汇总(1d/30d/全量)`。
- 测试：更新入口测试断言并新增“不可区分时不显示账号级 tokens”场景。
