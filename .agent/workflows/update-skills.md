# Workflow: update-skills

用于在对话结束或阶段性任务完成后，回顾对话过程，记录负反馈，并产出 Skills/Workflows 的迭代建议。

> 说明：本文档是 workflow 规范/指引，本身不会被“执行”；实际操作由 agent 按步骤对目标目录进行新建/修改。

## 目标

- 把「对话里暴露的问题」沉淀成可复用的规则（Skills）或可执行的流程（Workflows）
- 让下一次同类任务减少澄清、减少返工、提高一次通过率

## 触发条件

- 对话结束前（准备收尾总结时）
- 阶段性任务完成后（功能已跑通/PR 已准备好/关键问题已定位并修复）
- 用户出现明确负反馈（指出错误、流程不合规、反复澄清仍偏离预期）

## 路径范围

仅迭代以下目录下的内容（支持在范围内新建/修改对应文件）：

- `.agent/skills/`：Skills
- `.agent/workflows/`：Workflows

产物输出到（必须在范围内写入）：

- `.agent/CHANGELOG/update-skills/`：按日期记录复盘内容

安全边界（必须遵守）：

- 不触碰范围外任何文件/目录
- 优先做最小改动；不为“顺手重构/格式化”扩大影响面

不在范围内（默认不修改）：

- 项目其他业务目录
- 根目录下的临时/历史文档（除非明确要求迁移）

## 输入

- 对话历史（用户问题、澄清、代码改动、报错、用户反馈）
- 当前 `.agent/skills/` 与 `.agent/workflows/` 的现状

## 输出

- `.agent/CHANGELOG/update-skills/YYYY-MM-DD.md`：本次复盘记录
- 对 `.agent/skills/` 与/或 `.agent/workflows/` 的新增/修改（必要时才做）

## 习惯/风格学习（偏好沉淀）

当对话中出现“稳定的个人偏好/团队规范”时，需要把偏好沉淀成可复用规则，避免下一次重复确认。

触发信号（任一满足即可）：

- 用户明确表达偏好：语气/语言/输出格式/代码风格/目录结构/工具选择
- 用户对风格给出负反馈：太啰嗦、缺少链接、不要跑命令、不要改无关文件等
- 用户反复纠正同一类表达或行为（两次及以上）

沉淀方式（择一或组合）：

- 优先更新已有 Skill / Workflow：把偏好转为“触发条件 + 规则 + 例外 + 验收”
- 若偏好跨场景通用：新增一个“习惯/风格”类 Skill（放在 `.agent/skills/` 下，建议固定落到 `preferences.md`，集中维护）

要求：

- 偏好必须可执行、可验证（避免“更自然一点”这类不可验收表述）
- 明确适用范围与例外（例如：只对本仓库、只对 iOS、只对中文输出）

偏好结构约定（推荐字段）：

- `scope`：适用范围（全局/仓库/语言/平台/任务类型）
- `do`：必须做
- `dont`：禁止做
- `examples`：正例（1～3 条即可）
- `exceptions`：例外情况
- `validation`：如何验收（例如：输出必须包含哪些信息/必须避免哪些行为）

偏好分类（避免混淆）：

- 输出呈现偏好：语言、简洁度、是否使用标题/列表、文件链接格式等
- 行为偏好：是否允许运行命令、是否允许改多文件、是否允许创建新文件等

偏好冲突处理：

- 当新偏好与既有规则冲突：以“最近一次用户明确指令”为准
- 在 CHANGELOG 标注：冲突点、选择依据、对未来规则的更新动作（更新哪条 Skill/Workflow）

最小化澄清：

- 能从已沉淀偏好推断的，不再重复确认
- 仅当影响正确性/安全边界/路径范围时，才必须发起澄清

回归验证（确保真的学到）：

- 每次新增/更新偏好后，在下一次同类回复中至少显式对齐 1 条偏好作为自检点
- 若出现重复负反馈：优先把偏好写得更具体（补充 `exceptions`/`validation`），而不是继续口头记忆

## 验收标准

- CHANGELOG 文件按日期落盘，包含「负反馈」与「可执行的改进建议」
- 所有改动都限定在路径范围内，且能说明“为何改/改了什么/如何验证”
- 新增的 Skill/Workflow 具备明确触发条件、边界与步骤（可复用）
- 若存在明确的用户习惯/风格偏好：已沉淀到 `.agent/skills/` 或 `.agent/workflows/` 中，并在 CHANGELOG 记录“来源与验证方式”

## 执行步骤

1. **发起复盘（定量）**
   - 统计：澄清轮次、返工次数、一次通过率
   - 标注关键节点：用户目标、约束、成功标准、转折点
2. **记录负反馈（定性）**
   - 逐条列出用户明确指出的问题（不要“总结性模糊描述”）
   - 为每条负反馈补充：触发上下文、根因、影响范围
3. **沉淀 CHANGELOG（落盘）**
   - 在 `.agent/CHANGELOG/update-skills/` 下按日期新建文件
   - 写入：对话概览 / 使用到的 Skills&Workflows / 负反馈 / 自动扫描结果（如有）
4. **提出迭代建议（可执行）**
   - 把每条负反馈转成“下一次能直接照做”的规则/流程变更点
   - 明确：改动位置、改动内容、验证方式
5. **迭代 Skills / Workflows（范围内变更）**
   - 仅对 `.agent/skills/`、`.agent/workflows/` 做新增/修改
   - 新增时：优先补齐触发条件、路径范围、输入输出、步骤、反例/边界
6. **通知用户（收尾）**
   - 1～3 句总结：本次核心问题、已采取的改动、下次预期改善点
