结果：定位到用量展示与 CodexBar 不一致的核心原因（used% vs left% 口径差异），以及账号/plan/credits/cost 缺失是“Providers 未透出/未映射到通用视图”的问题；另外确认 GUI/测试环境出现 “Codex CLI missing” 多数是 PATH/env 继承问题（终端可运行但子进程找不到），需要在自研 `SKProcessRunner` 侧补齐 login shell env 合并策略。

## 1. 本次使用的 Skills / Workflows

- `preferences.md`（用于约束“只改 .agent/*”与输出语言）

## 2. 负反馈记录
1. **用量数据与 CodexBar 对不上**：Nolon 显示为 `usedPercent`，CodexBar 显示为 `remainingPercent`（xx% left），导致 UI 看起来互相矛盾。
2. **account / plan / credits / cost 没有显示**：说明 `libs/Providers` 对外模型/descriptor 未提供这些字段或 Nolon 通用视图未消费，造成信息缺失。
3. **GUI/测试环境提示 “Codex CLI missing” 但终端可运行**：子进程拿到的 PATH/env 不完整，导致 `codex` 在 app/test 里找不到。
4. **编译错误（module import/依赖缺失）**：`UsageMonitorSettingsStore.swift` 报 “Initializer ... missing import of defining module 'ProviderUsage'”，暴露出跨 target 依赖/`import` 约束在迁移过程易被遗漏。
5. **CodexBar 仅作参考，不直接集成**：需要在流程中明确“对齐行为/数据口径，但不引入依赖”。

# 追加：MCP 功能迭代复盘 - 2026-02-03

## 0. 对话概览
目标：让 MCP 卡片点击打开 WebView 配置编辑页；MCP 缓存迁移到 `~/.nolon/mcps` 支持“逐个迁移”，并在已迁移/不一致时给出明确 UI（隐藏迁移 / 显示更新）；同时修正 OpenCode 的 MCP 配置文件路径与格式。

结果：实现逐个 MCP 迁移 + diff 检测（迁移/更新按钮）与 “一 MCP 一文件” 的缓存策略；修正了 OpenCode MCP 配置路径/格式假设（原先按 `mcp_settings.json`/`mcpServers` 处理导致错误）。

## 1. 本次使用的 Skills / Workflows
- `/update-skills`
- `preferences.md`

## 2. 负反馈记录
1. **“编辑 MCP”打开了旧表单**：期望是 WebView 直接编辑配置文件，而不是表单（老组件应移除）。
2. **MCP 迁移应逐个而非全部**：用户需要按 MCP 单独迁移；已迁移的卡片不再显示迁移入口；配置不一致时显示“更新”按钮。
3. **OpenCode MCP 配置路径/格式推断错误**：用户明确指出当前配置文件路径不对，并给出官方文档链接作为依据。
4. **输出中出现“伪引用”风险**：当无法实际打开链接或未验证来源时，不应使用看起来像已验证的“引用/证据”格式（避免误导）。

## 3.5 习惯/风格学习（偏好沉淀）
- **官方链接优先**：涉及配置文件路径/格式时，只要用户给出官方文档链接，就以官方为准，避免靠记忆猜测。
- **MCP 迁移交互**：默认“逐个迁移 + 状态驱动 UI（迁移/更新/隐藏）”，避免一次性批量操作。

## 4. 现有 Skills / Workflows 迭代建议
### `preferences.md`
- 新增：官方链接优先对齐、避免伪引用、MCP 逐个迁移 + 状态驱动 UI。

## 5. 新增 Skill / Workflow 建议
### 新增 Skill：`mcp-config-formats.md`
- 目的：固化“不同 provider 的 MCP 配置路径/格式”检查清单（例如 OpenCode 的 `mcp` vs 常见 `mcpServers`），以及迁移/更新的对比规范（type/env/headers 等字段保留）。
 - 验证：修改后能正确读取计数、编辑正确文件、迁移/更新按钮状态正确。
